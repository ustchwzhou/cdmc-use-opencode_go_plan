Prerequisites

前置条件与关键配置

  • Command Code 已安装；本方案验证版本为 1.22.0。
  • cc-switch 正在本机监听 http://127.0.0.1:15721。
  • cc-switch 的 Claude 通道当前 Provider 已配置为 OpenCode Go。
  • OpenCode Go 套餐与鉴权在 cc-switch 中可以正常调用。
  • Claude Provider 的“默认兜底模型”必须留空。
为什么兜底模型必须留空？Mod 发送裸模型名，例如 deepseek-v4-flash。若设置了默认兜底，不包含 sonnet / opus / haiku / fable 的模型名可能被规则吞掉并改写。Sonnet、Opus、Haiku、Fable 的角色别名映射可以保留。

Implementation notes

核心实现要点

1. Provider 命名空间和启用条件

Provider ID 为 opencode-go，模型为 opencode-go/<model>。只有 CMDC_USE_OPENCODE_GO=1 时注册，保证同一安装可以随时回到官方 Provider。

2. Anthropic Messages 协议适配

将 system、assistant、user、tool result 与工具 schema 转为 Anthropic Messages 请求；移除模型前缀后发送到 cc-switch 的 /v1/messages。

3. 流式事件状态机

解析 content_block_start、content_block_delta、content_block_stop、message_delta 和错误事件，分别维护 text、thinking、tool-use 状态并通知 TUI。

4. 工具调用闭环

累计 input_json_delta，生成完整 tool-use block；Command Code 执行工具并返回 tool result 后，允许模型发起第二次请求。只测试普通聊天不足以证明 Agent 真正可用。

5. 错误与用量

代理不可达、HTTP 非 2xx、Anthropic error event，以及流结束但没有回答或工具调用时均抛出明确错误；Token usage 增量合并，避免后续事件抹掉输入 Token。

Lessons learned

踩过的坑与得到的经验

模型显示正确 ≠ Provider 可用

标题栏只证明 ID 被设置，不能证明网络、协议和 UI 回调全部打通。

最终字符串可用 ≠ 交互流可用

--print 曾有答案，但 TUI 没收到 delta，因此只显示 Worked。

回调是接口契约

direct transport 必须触发流式 callbacks；Promise 最终返回不能替代它。

短模型名存在冲突

内置 /model 可能选中官方 canonical ID，必须使用完整命名空间。

兜底规则会改写模型

请求返回不代表命中目标模型，需要检查 cc-switch alias 与 fallback。

验证完整 Agent 回合

最低验收应覆盖文字、Thinking、tool_use、工具结果和第二次响应。

推荐调试顺序代理健康 → 原始 SSE → Provider 最终返回 → 流式 delta → 强制工具调用。这样能快速区分网络、协议、回调和 Agent 循环问题。
Troubleshooting

常见问题排查

显示 “Worked for …”，但没有回答
完全退出旧进程后重新运行 cmdc-d。仍有问题时检查是否出现 text_delta，不能仅依据退出码 0 或请求完成判断成功。
/model 仍显示官方模型
这是内置目录和短名称解析造成的混淆。改用 /og-model 查看、切换；用 /opencode-go-status 检查 Provider。
选择 A 模型，实际似乎请求 B 模型
检查 cc-switch Claude Provider 的“默认兜底模型”，应留空；并确认 Claude 通道当前 Provider 是 OpenCode Go。
代理不可达或 HTTP 错误
确认 cc-switch 监听 15721，并执行健康检查。若端口变化，同步修改 Mod 中的 CC_SWITCH_URL。
修改 Mod 后行为没变化
Mod 在启动时加载。结束全部旧进程后重启，并运行 cmdc-d mods list，确认只加载一个 opencode-go。
工具调用停住或 JSON 参数不完整
检查 input_json_delta 是否完整累计，block stop 时是否生成有效 tool-use；工具结束后还应出现第二次 model request。

Operations

回退、升级与维护

临时回退

cmdc-d --command-code

本次进程不注册 OpenCode Go，直接使用官方 Provider，无需删除文件。

长期停用

将 opencode-go.ts 移出当前 HOME 的 .commandcode\mods，或持续使用 --command-code。不要修改官方 cmdc.cmd。

Command Code 升级后

  • 运行 cmdc-d mods list，确认 Mod 仍能加载。
  • 重新执行文字 delta 测试和一次工具调用测试。
  • 若 ModApi 回调契约变化，以新版官方 Provider 的流消费行为为准适配。
  • 以本目录文件作为可复现基线，再修改正式安装副本。
维护原则不向 node_modules\command-code 打补丁。适配全部放在 Mod 和自定义启动器中，避免 npm 更新覆盖，也避免官方代码与本地修改互相污染。
